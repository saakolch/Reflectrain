## Why this order

The cheapest mistake to fix is a wrong interface. The most expensive one is a wrong data model
and a wrong AI prompt, because they decide what the app can ever remember.

So: interface first (mockup), then data shape, then AI contract, then code, then keys.

## Mechanism, in plain words

- Dump is a single text box + one button. No structure required from you — that is the AI's job.
- The AI never writes to the database directly. It returns a proposal; you tick what is true; then it saves.
  This is the anti-hallucination and anti-clutter mechanism. Cost: one extra tap.
- Active insights are capped at 5. A cap is what stops the system from becoming a second inbox.
- Every insight must carry a *practice*, a *cue* (when), and an *evidence question* (how you will know).
  Insight without practice is a note, and notes do not change behaviour.
- The Self tab holds claims ("I am someone who acts before feeling ready"), broken into 3 observable
  actions. Each action you do becomes a dated evidence row, and confidence moves only when evidence exists.
- Weekly: same box, different mode. Progress / Resistance / Changes / Next sprint, plus an
  "update the ledger" step.

## Order of work after you approve the draft

2. I scaffold Next.js + Supabase schema + `/api/analyze` with a mock AI (works with no key), so the loop is visible.

4. You open the URL on the phone, add to home screen, run one real weekly dump.

## What I deliberately skip in v0

- Push notifications (iOS web push is unreliable for this; a daily manual check + one card is enough).
- Vector search / embeddings / agents — not needed under ~2000 entries.
- Two-way Obsidian sync. One-way export (Markdown) later; import is a one-time script.
- Multi-user, sharing, teams.

## Risk I am watching

Over-structuring. The app must stay faster than iPhone Notes, otherwise it dies like every
other productivity tool. Guardrail: capture must be ≤2 taps to start typing, and the AI preview
must never block saving.
