# App build — what was built and why (1 Nov 2026, ~19:45 Asia/Shanghai)

Name note: Windows forbids `:` in file names, so the time is written with `-`.

## Goal of this step

Turn the approved draft into a running skeleton: the loop must be visible on screen and able to store
a real dump, even before the DeepSeek key exists.

## Elements built (and the reason for each)

| Element | Path | Why |
|---|---|---|
| Next.js app shell + 4 tabs | `app/(app)/layout.tsx`, `components/TabBar.tsx` | One place where the loop lives; tabs are the navigation the draft promised |
| Dump screen with confirm step | `app/(app)/dump`, `components/DumpComposer.tsx` | Capture must be 2 taps; the confirm step is the anti-hallucination mechanism |
| Analyze endpoint | `app/api/analyze/route.ts` | Key stays server-side; one contract for daily and weekly |
| Prompt + JSON normaliser | `lib/prompts.ts`, `lib/ai.ts` | The prompt is the product's brain; normaliser protects the DB from malformed JSON |
| Mock fallback | `lib/ai.ts` (`mockProposal`) | Loop testable with zero keys; also the failure path when the API is down |
| Insights ledger | `app/(app)/insights` | Practice + evidence + counter-evidence on each card |
| Plan / sprint | `app/(app)/plan` | Outputs are checkable tasks, not prose |
| Self claims | `app/(app)/self` | Claim → 3 actions → dated evidence → confidence |
| Schema + RLS | `supabase/migrations/0001_init.sql` | The tables are the real skeleton; RLS keeps one user's data private |
| Setup screen | `app/setup`, middleware rewrite | Without keys every page would throw; now it explains what is missing |

## Decisions (and why)

- **No Tailwind.** One hand-written stylesheet equals the mockup exactly, with no build-tool surface to
  break. Cost: no utility classes; benefit: everything looks the same as the draft.
- **Server actions instead of REST mutations.** Fewer moving parts: forms work without client JS.
- **`user_id` defaults to `auth.uid()` in SQL.** Inserts in code never pass a user id, and RLS still
  guarantees ownership. Removes a whole class of bugs.
- **Evidence as `jsonb` on the row.** One user, few rows; a join buys nothing yet.
- **Middleware rewrite to `/setup`.** A layout guard cannot stop a page from rendering, so the guard
  belongs in front of rendering. This was found by running the app, not by the compiler.
- **No caps enforced.** Per your call: test the loop first; the UI only reports counts.

## Verification done

- `npm run build` → 12 routes, 0 type errors, 0 lint errors.
- `npm run dev` → `/login` 200, `/` 307 → `/dump`, `/setup` reachable.
- Missing-key path → `/setup` renders “Connection details are missing”, no server error.
- Not verified yet (needs real keys): sign-up, RLS queries, DeepSeek round-trip.

## Open risks

1. Untested against the real Supabase project — first login is the real test.
2. DeepSeek model id must match the dashboard; wrong id → 404 → silently falls back to mock, which looks
   like success. The UI prints the mock notice, but it is easy to miss.
3. The weekly upsert depends on a unique `(user_id, week_start)` constraint — present in the migration,
   so the migration must be run before the first weekly dump.

## Lessons recorded

- `npm run build` while `next dev` is running corrupts `.next` and the dev server starts throwing
  `__webpack_modules__[moduleId] is not a function`. Fix: kill dev, delete `.next`, restart. Do not run
  the two side by side.
- Windows file permissions on this folder blocked the shell entirely (sandbox could not grant write).
  Fixed by a single diagnosed ACL grant; backup + rollback script live in `C:\Users\stakol\dsh-acl-recovery`.
